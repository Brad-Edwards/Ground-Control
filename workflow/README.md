# Workflow Platform

This directory contains the portable `/implement` workflow release surface. It
is part of Ground Control because this repository is both the engine host and
the first consumer.

## Layout

- `engine/`: versioned engine metadata. `engine/engine.yaml` names the engine,
  capability vocabulary, included release surfaces, and release artifact paths.
  The live engine source is in `mcp/ground-control/`.
- `packs/`: source for supported gate packs. Each pack contains `pack.yaml`,
  `capabilities.yaml`, `classifier.yaml`, `templates/`, `installer.mjs`, and
  `selftest/`.
- `tools/`: release, install, self-test, gate-runner, and eval commands.
- `evals/`: deterministic workflow-engine eval definitions.
- `gate-catalog.json`: the checked-in registry that maps engine and pack
  versions to release artifacts, checksums, compatibility ranges, signer
  metadata, and trust policy.
- `releases/`: ignored release tarballs generated by the materializer.

The seven initial packs are `rust-cargo`, `python`, `jvm-gradle`,
`jvm-maven`, `node-ts`, `cpp-cmake`, and `docs-generic`.

## Release And Materialize Flow

Run the materializer from the repository root:

```bash
node workflow/tools/materialize-pack-registry.mjs
```

The materializer regenerates pack metadata and templates from the platform
definitions in the script, writes `workflow/engine/engine.yaml`, builds
deterministic release tarballs under `workflow/releases/`, and rewrites
`workflow/gate-catalog.json` with Secure Hash Algorithm 256-bit (SHA-256)
checksums. `workflow/releases/` is ignored because release tarballs are build
artifacts, not source.

Validate the release catalog and artifact checksums with:

```bash
node workflow/tools/verify-workflow-release.mjs
```

Run the workflow-engine eval suite with:

```bash
node workflow/tools/eval-workflow-engine.mjs
```

Run a pack self-test with:

```bash
node workflow/tools/selftest-pack.mjs --pack docs-generic
```

## Consumer Install Flow

Consumers install or upgrade one pack at a time through the MCP tool
`gc_install_workflow_assets` or the local wrapper:

```bash
node workflow/tools/install-workflow-assets.mjs \
  --repo /absolute/path/to/consumer \
  --pack node-ts \
  --version '^1.0.0' \
  --engine-version '^1.0.0' \
  --scope frontend \
  --profile react-vite \
  --mode install
```

The installer verifies release-artifact checksums, writes `.gc/gates.yaml`,
writes `.gc/workflow-lock.json`, updates `.ground-control.yaml`, copies pack
templates into `.gc/gate-packs/<pack-id>/`, optionally installs declared
development dependencies, runs the pack self-test, and vendors consumer
artifacts under `.gc/vendor/ground-control/`.

Ground Control is the engine host. When the target repository contains
`mcp/ground-control/lib.js`, the installer skips `.gc/vendor/` and reports
`vendoring.status: "skipped"`. The host uses the source engine in
`mcp/ground-control/` and the source packs in `workflow/packs/`.

## Gate Runner

The local wrapper runs the same engine as `gc_run_gates` but does not post
phase markers:

```bash
node workflow/tools/run-gates.mjs \
  --repo /absolute/path/to/repo \
  --issue 1234 \
  --base origin/dev \
  --head HEAD \
  --capabilities format,lint,unit_tests,policy
```

Use the MCP tool during `/implement` when marker writes are required.
