### Added

- **Key Risk Indicator monitoring (GC-T007)**: New `KeyRiskIndicator`
  aggregate with two-breakpoint threshold classification
  (`GREEN` / `YELLOW` / `RED`) and a configurable direction
  (`HIGHER_IS_WORSE` default, `LOWER_IS_WORSE` for inverted metrics like
  patch coverage). A RED measurement publishes a synchronous
  `KriBreachedEvent` consumed by `ReassessmentSignalService`, which fans the
  `KRI_BREACH` reassessment signal out to assessments under the KRI's
  linked risk register record or scenario—the listener is
  `@EventListener` (NOT `@TransactionalEventListener`), so a listener
  failure rolls back the measurement write atomically.
  CRUD lives at `/api/v1/key-risk-indicators`; new measurements post to
  `POST /{id}/measurements`.
- New `KriThresholdBand` enum mirrored at the frontend
  (`KRI_THRESHOLD_BANDS`) and MCP boundaries per ADR-034.
- Extended `ReassessmentTriggerCategory` with NIST §3.4 monitoring
  categories (`THREAT_CHANGED`, `VULNERABILITY_CHANGED`,
  `PREDISPOSING_CONDITION_CHANGED`, `OBSERVATION_CHANGED`,
  `TOPOLOGY_CHANGED`, `ENVIRONMENT_CHANGED`, `KRI_BREACH`) and
  `ReassessmentTriggerTargetType` with the new lifecycle aggregates
  (`RISK_APPETITE_PROFILE`, `RISK_ASSESSMENT_CAMPAIGN`,
  `KEY_RISK_INDICATOR`, `OBSERVATION`, `THREAT_MODEL`).
