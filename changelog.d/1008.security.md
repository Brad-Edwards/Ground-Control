Research privacy, security, and prompt-injection controls (ADR-085): research runs snapshot their high-risk operation policy at start (allowed-tool inventory, a structured default-deny data-egress policy, and display-only privacy constraints) so later intake edits cannot re-authorize an active run. A durable, run-scoped `ResearchRunOperationAuthorization` record now governs generated-code execution, browser activity, lab/hardware actions, and external writes: a request lands `PROPOSED`, an admin/operator decision moves it to `APPROVED`/`DENIED` only when the run's egress policy permits the `(dataClass, destinationClass, requestedForm)` tuple (an `AUTONOMOUS` run may propose but never approve), and a one-time-use approval is spent to `CONSUMED`. Research artifacts can record a privacy/access `dataClass`, and all policy/authorization fields are closed enums built only from structured, service-validated inputs so retrieved/untrusted content can never set tools, egress, sandbox, or approval state. Exposed over REST (`/api/v1/research-runs/{runId}/operation-authorizations/**`, decision route admin-gated) and the `gc_research_operation_authorization` MCP tool.
