### Added

- **LLM activities and provider boundary (GC-O009 phase 5, ADR-028)**: a
  Temporal-neutral, provider-neutral LLM invocation port (`domain/llm/`:
  `LlmProvider`, `LlmCompletionRequest`/`LlmCompletion` with redacted
  `toString()`, `ResolvedLlmRoute` closed safe scalar set, `TrustedRouteResolver`,
  `PlanPublicationPort`) plus the canonical `anthropic` infrastructure adapter
  (`infrastructure/llm/`: `LlmProviderRegistry` modeled on
  `PackTypeHandlerRegistry`, `AnthropicLlmProvider` over Spring `RestClient`
  with bounded timeouts/output tokens/response size and no body/header wire
  logging, redacted `AnthropicProperties`). Route resolution and plan
  publication sit behind domain ports whose production implementations
  (`BridgePendingRouteResolver`, `BridgePendingPlanPublisher`) fail closed with
  `ServiceUnavailableException` until the ADR-081 normalized-config/publication
  bridge (#1281) lands—a deliberate, tested, secure production behavior, not
  a placeholder. `WorkflowExecutionService` resolves the `planning`-stage
  route before `WorkflowControlPort.start`, so a caller-supplied provider,
  model, endpoint, credential, prompt, or completion can never reach the
  public start request, and a normal start never creates a workflow already
  known to be unrunnable.
- `mcp/ground-control/lib.js` (ADR-027 amendment): the routing parser now
  accepts the canonical provider id `anthropic` and normalizes the legacy
  `claude` label to it in every output, keeping Java free of a second
  provider-alias table.
- ArchUnit rules proving the deterministic `/implement` activity seam
  (`ImplementActivities`/`ImplementActivitiesImpl`) is structurally unable to
  reach the LLM port, registry, or provider adapters, and that no class
  outside `infrastructure/llm/anthropic/` calls the Anthropic provider
  directly (ADR-082 rule-ownership row).
- `contracts/schemas/workflow/content-activities.v2.schema.json` retires
  `content-activities.v1`: `AuthorPlanInput` gains required `project` and
  `route` (`ResolvedLlmRoute`) fields so `authorPlan` resolves a trusted,
  project-scoped LLM route instead of inferring project ownership from the
  issue number. `implement-workflow.v1.schema.json` gains an additive,
  optional `ImplementWorkflowInput.route`, bound to the execution once at
  start time.
- `ImplementContentActivitiesImpl` composes `LlmPlanAuthor` (the sole
  LLM-backed collaborator: resolves the provider for the already-bound
  route, builds the prompt inside the activity process, and hands the
  completion to `PlanPublicationPort`) so the provider dependency reaches
  only `authorPlan`; the other content-activity seams fail closed pending
  #1281. A dedicated `LlmActivityOptions` bounds the seam's Temporal
  timeout/retry policy and marks `DomainValidationException` non-retryable,
  in place of `ImplementActivityOptions.standard()`/`longRunning()`.
- Non-leak acceptance evidence runs in the normal unit/Sonar lane (no
  Testcontainers): sentinel prompt/completion/key/error-body tests on
  `AnthropicLlmProvider`, and `LlmContentActivitySentinelNonLeakageTest`,
  which runs the real content-activity seam through `TestWorkflowEnvironment`
  and proves a sentinel completion never reaches the serialized Temporal
  execution history, the propagated workflow failure, or captured Logback
  events. `WorkflowExecutionControllerTest` proves LLM-route misconfiguration
  reaches the client only through the standard `ErrorResponse` envelope.

Satisfies GC-O009 phase 5 (ADR-028 LLM provider boundary).
