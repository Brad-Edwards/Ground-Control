### Fixed

- GC-I004 compliance drift monitor: the evidence-expiry sweep now wraps each
  per-artifact `publishEvent` dispatch in its own `REQUIRES_NEW`
  `TransactionTemplate` execution, so the synchronous
  `ComplianceDriftDetectorService` listener receives a fresh writable
  transaction instead of joining the sweep's outer (previously read-only)
  context. Before the fix, the listener's `compliance_drift_event` INSERT
  was silently dropped under the read-only context, or a single per-artifact
  failure would roll back the entire batch while `lastSweepAt` still
  advanced—producing the exact 'stalled monitor silently reports
  compliant' mode the cluster scope was meant to prevent. Annotated
  `ComplianceDriftEventRepository.acknowledgeIfUnset` with
  `@Modifying(clearAutomatically = true, flushAutomatically = true)` so the
  acknowledge endpoint re-reads the persisted row rather than returning the
  pre-update entity cached in the L1. Added
  `EvidenceExpirySweepIntegrationTest` against real `ApplicationContext` +
  Testcontainers Postgres so the sweep -> listener -> DB-row path is now
  covered end-to-end. Flyway migrations renumbered V131-V134 → V135-V138 for
  merge-order coexistence with prior PRs; `MigrationSmokeTest` and
  `RequirementsE2EIntegrationTest` updated to match. Transactional self-injection
  in `ComplianceDriftDetectorService.acknowledge` and
  `EvidenceArtifactService.listByProjectFilteredByExpiry` resolved by calling
  repository methods directly. `ComplianceDriftDetectorService.publish` parameter
  count reduced via a private `DriftEventSpec` record. Removed invalid `@Autowired`
  annotation from `EvidenceExpirySweepConfig` `@Bean` method parameter. Extracted
  nested ternary in `EvidenceArtifactController` to an explicit if/else block.
  Removed duplicate `EvidenceType` and `EvidenceSourceKind` type declarations
  from `frontend/src/types/api.ts` that were introduced when the GC-Q012 Explorer
  types were added; the canonical declarations already exist in the GC-M016 section.
